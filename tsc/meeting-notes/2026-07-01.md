**1. Welcome & introductions**

Roundtable — attendees introduced themselves.

EnerGNN recap: a Graph Neural Network library for real-life energy networks, built on JAX and Flax.
- `energnn.graph` — Hyper Heterogeneous Multi Graph (H2MG) representation, built to process real-life full-scale complex systems without preprocessing.
- `energnn.model` — compatible GNN library.
- `energnn.problem` — interface to apply EnerGNN to a given use-case.
- `energnn.trainer` — core training loop.

**2. Role of the TSC & governance framework**

The TSC is the project's leadership body. Its role:
- Set the overall direction of the project.
- Ensure the community has the resources and infrastructure needed to succeed.
- Resolve issues within the project community.
- Report updates to the LF Energy TAC and the wider community.
- Participate in code review and feature discussions.

**Composition**
- Primarily the project's committers/maintainers, plus key stakeholders and dedicated users where relevant.
- Doesn't have to exactly match the committer list, but should stay close — committers are generally expected to be voting TSC members.
- The TSC will audit its own membership annually.
- Functions as a "do-acracy": members are expected to actively contribute time, code, and expertise on a regular basis.

**Meetings & notes**
- Open to any attendee (rare exceptions allowed).
- Published on the LFX calendar.
- **Cadence decided: 1st Wednesday of each month, 10am.**
- Notes taken and posted publicly for every TSC meeting — likely hosted in a dedicated governance repo (see action item #1).

**Communication**
- Maintainers keep roadmap, feature planning, and release cadence public.
- Updates posted as needed to the project Slack channel / mailing lists.
- Maintainers are expected to be responsive to community issues and questions.

**5.1 Release cadence**
- Historical data point: v0.1.0 → v0.2.0 took about 4 months (Nov 2025 → Mar 2026).
- **Decision: regular releases every quarter.**

**5.2 Code quality / CI**
- **Decision: introduce SonarQube/SonarCloud.**
- **Decision: quality gates blocking merge — yes, minimum coverage 90%.**
- Current CI state on `energnn` and `pypowsybl-to-energnn` to be confirmed (follow-up outside the meeting).
- **AI-assisted commits will not be flagged/treated differently.**
- Cross-review of contributions required — **no auto-merge** allowed.
- Code quality/clarity matters for reviewers, but **no formal style guideline exists yet.**

**5.3 Merge rights on `main`**
- Merge rights: restricted to the maintainer list (see 5.4).
- **Required reviews before merge: 1.**
- Mandatory cross-institution review (RTE/ULiège) for sensitive PRs: **not feasible at this time.**
